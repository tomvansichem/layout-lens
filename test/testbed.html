What this testbed shows

  • Padding / margin / element size on hover — fully working (A1–A3).
  • redSize mismatch — CSS box size vs painted size. Fires on CSS transforms on the element (B1–B3) or any ancestor (B4). These are the cases where the layout box and the painted box genuinely differ.
  • amberClipped content — content larger than the box with overflow: hidden / clip and no scrollbar to reach it (B11, B12, B14, including text-overflow: ellipsis truncation). Reports how many pixels are hidden.
  • quietMatching sizes (B5–B7), overflow:hidden with no overflow (B13), and user-scrollable containers (B15) stay in the plain hover state.
  • names itAdvisory tooltip lines — a min/max-width|height clamp (B9) and an element wider than the viewport (D1). Neither changes the outline; they explain a size without claiming it's a bug.
  • gapStill not flagged, by design: zoom on modern Chrome (B8), flex-shrink (B10), and sub-pixel rounding (C1) — getComputedStyle() already returns the post-layout used value, so there is nothing to compare against. The README's discrepancy claim covers transforms and overflow clipping; min/max clamping (B9) is now named via an advisory line even though it still doesn't trigger the red check itself.
